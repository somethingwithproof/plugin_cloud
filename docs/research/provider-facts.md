# Provider facts: documentation check

Documentation half of [#16](https://github.com/somethingwithproof/plugin_cloud/issues/16) (DigitalOcean), [#17](https://github.com/somethingwithproof/plugin_cloud/issues/17) (AWS), [#18](https://github.com/somethingwithproof/plugin_cloud/issues/18) (Google Cloud), and [#19](https://github.com/somethingwithproof/plugin_cloud/issues/19) (Azure), run 2026-11-14. Question: does each row of the plan's provider fact tables still match the provider's own documentation, and which rows can only a live call settle?

**Result.** Every row was re-read against the cited page. Four plan statements changed: DigitalOcean's `per_page` maximum is 200 for the endpoints the plugin uses; CloudWatch accepts AWS JSON 1.0 as well as the Query protocol; MQL still runs although support ended; and Azure's free million metrics calls is per subscription. Prices previously unknown (CloudWatch `ListMetrics`, Azure metrics queries) are now sourced in the [cost model](cost-model.md). The rows that only a live account can settle are listed under [Live checks](#live-checks), with the exact calls to make.

Method: public documentation pages, public API specifications, and public price feeds only. No credentials were used and no provider API was called with credentials.

Status values: **confirmed**, **corrected** (the plan text is wrong or out of date), **unverified** (no official statement found, or only a live test can settle it), **not rechecked** (not on the task's priority list and not fetched or only partly fetched).

Quotes are verbatim and under 30 words. Where the page was rendered by a script and was read through a text extraction, that is noted.
