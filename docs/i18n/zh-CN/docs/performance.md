<a id="performance"></a>
# 性能

这是为 [#47](https://github.com/somethingwithproof/plugin_cloud/issues/47) 于 2026-11-15 使用 [`tests/bin/perf.php`](../../../../tests/bin/perf.php) 进行的测量。CI 在每项 Cacti 和 PHP 作业运行相同脚本。仅当 1,000 个序列无法在一个轮询间隔内完成时才使作业失败；由于运行器硬件不同，只输出耗时，不进行耗时比较。

**结果。** 使用本地测试数据服务器且不增加延迟时，一次采集运行约 3 秒读取 1,000 个序列，即每次请求约 3 ms 的插件及 TLS 处理。健康页面在 0.08 秒内呈现 10,000 个缓存序列。每次请求加入 100 ms 的模拟提供商延迟后，同一运行耗时 106 秒。能否在一个轮询间隔内完成 1,000 个序列，取决于提供商延迟。

<a id="what-runs"></a>
## 运行内容

脚本使用真实采集器、DigitalOcean 驱动、受保护传输（操作允许列表）和套接字传输，并使用测试 CA 验证 TLS。仅在操作检查后重写主机，使请求到达 [`tests/bin/perf-server.php`](../../../../tests/bin/perf-server.php)，而非 `api.digitalocean.com`。该服务器重放已记录的测试数据，将时间戳平移到当前时间，并发送驱动读取的速率限制头。

| 场景 | 设置 | 测量内容 |
|---|---|---|
| 采集 | 4 个账户，每账户 50 个 Droplet，每 Droplet 5 个序列（CPU 和四项带宽）：共 1,000 个序列 | 轮询器 1 上的一次采集运行（REQ-PERF-001） |
| 预算 | 1 个账户，200 个 Droplet，每个 5 个序列：共 1,000 个序列 | 相同运行，但请求预算会停止该账户 |
| 页面 | 10 个账户，每账户 200 个 Droplet，每 Droplet 5 个缓存序列：共 10,000 个序列 | 以已登录管理员身份通过 HTTP 访问 `cloud_health.php`，预热后五次加载的中位数（REQ-PERF-002） |

采集场景使用四个账户，因为每个 DigitalOcean 令牌允许每分钟 250 次请求。请求份额为 100% 时，这也是一个账户每次运行的最大读取量（`RequestBudget::perRun`）。预算场景体现此限制：账户读取 250 个序列，将其余 750 个标记为未读取，原因为 `budget`，健康页面会报告此情况。

<a id="results"></a>
## 结果

每个 Cacti 版本运行三次，不增加延迟：

| 场景 | Cacti 1.2.31 | Cacti 1.2.x |
|---|---|---|
| 采集，4 个账户共 1,000 个序列 | 2.83、3.00、3.17 秒；1,000 次请求读取 1,000 个 | 3.42、2.59、2.61 秒；1,000 次请求读取 1,000 个 |
| 预算，1 个账户共 1,000 个序列 | 1.20、1.32、1.10 秒；读取 250 个，750 个因 `budget` 留待后续 | 1.24、1.72、1.10 秒；读取 250 个，750 个因 `budget` 留待后续 |
| 健康页面，10,000 个序列 | 三次运行的中位数均为 0.08 秒，最慢均为 0.08 秒 | 中位数 0.08 秒，最慢不超过 0.09 秒 |

使用 `perf.php <url> 100` 在每次测试响应前增加 100 ms 延迟时，Cacti 1.2.31 的采集场景耗时 106.26 秒，读取全部 1,000 个序列。预算场景耗时 27.02 秒。

页面结果也按内容验证，而非仅测速度。10 个账户各显示 1,000 个当前序列，以及每小时 12,000 次请求的估算（每 300 秒读取 1,000 个序列）。

<a id="reading-the-results"></a>
## 解读结果

- **运行时间随提供商延迟增长。** 采集器每请求读取一个序列，一次执行一个请求。耗时约为请求数 ×（延迟 + 3 ms）。在默认 240 秒预算下，平均往返时间低于约 237 ms 时可完成 1,000 个序列。超过该值时，采集器达到预算便不再开始新账户，未读取的账户将在下次运行采集。首次[实际检查](../../../research/provider-facts.md#live-checks)（#16）从家庭连接测得往返中位数 384 ms（301 至 799 ms）。此延迟下 1,000 个序列约需 390 秒，因此默认预算每次约读取 620 个，其余延后。靠近 DigitalOcean 的数据中心内的轮询器预计延迟更低；在规划单个轮询器超过约 600 个序列之前，请先从自己的轮询器测量。
- **DigitalOcean 的限制按令牌计算。** 默认份额为 50% 时，一个账户每次读取 125 个序列。更大规模需要更多账户，各自使用独立令牌；健康页面的估算会显示每账户距其份额上限还有多少。
- **10,000 个序列时页面开销仍低。** 页面仅读取缓存行，从不调用提供商，因此开销随插件表增长，而不随提供商延迟增长。
- **此处未测量：** Cacti 轮询器的 RRD 更新、boost、Spine、远程采集器及位于独立主机的数据库。这些均会带来插件之外的额外开销。

<a id="running-it"></a>
## 运行方法

使用可丢弃的数据库，已安装并启用插件，且可通过某个 URL 访问 Cacti：

```sh
CLOUD_TEST_DATABASE=disposable php plugins/cloud/tests/bin/perf.php http://127.0.0.1:8080/cacti/
CLOUD_TEST_DATABASE=disposable php plugins/cloud/tests/bin/perf.php http://127.0.0.1:8080/cacti/ 100
```

第二个参数为每次测试响应增加对应毫秒数的延迟。脚本会删除插件的全部账户、资源、序列和观测，并重置管理员密码，因此绝不要在需保留的数据库上运行。
